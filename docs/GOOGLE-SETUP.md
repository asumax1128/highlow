# Googleスプレッドシート版の接続手順

既存のFACTOR×FACTOR用 `doGet` / `doPost` と `ranking` シートは変更しません。提供されたv8 APIは得点と捕獲数を受け取り、固定期間・上位20名・名前で重複除外する仕様です。HIGH×LOWの検証や期間別ランキングに必要なデータを持たないため、直接流用しません。Google Apps Scriptとスプレッドシートを利用する方式は共通です。

## 新規インストール（管理者が1回実施）

1. https://script.google.com/ で、**新しい独立したプロジェクト**を作成します。既存ゲームのApps Scriptは開いても上書きしないでください。
2. `apps-script/Code.gs` の内容を新プロジェクトの `Code.gs` に貼り付けます。これは問題エンジン・採点・検証・保存処理をまとめた生成済みファイルです。手で別の採点ロジックを追加する必要はありません。
3. プロジェクトの設定でタイムゾーンを `Asia/Tokyo`、ランタイムをV8にします。必要ならマニフェストに `apps-script/appsscript.json` を使ってください。
4. エディタ上で `createHighLowStorage` を1回実行してGoogleの権限を許可します。新しいHIGH×LOW専用スプレッドシートが作成され、`HIGHLOW_SPREADSHEET_ID` がスクリプトプロパティに設定されます。既存シートは使用しません。実行ログに新しいシートのURLが出ます。すでに保存先がある場合は重複作成を拒否します。
5. スプレッドシートそのものの共有設定は非公開のままにします。生のトークンは保存しませんが、識別情報のハッシュや回答情報が含まれます。
6. テスト用Webアプリとして新規デプロイします。「次のユーザーとして実行」は管理者自身、アクセスはブラウザから匿名APIを呼べる設定が必要です。`/exec` のURLを控えます。Googleの組織設定で匿名公開できない場合は、その制限を解除せず管理者と確認してください。
7. `dist/config.js` を実際のURLで設定します。

```js
window.HIGHLOW_RANKING_CONFIG={
  endpoint:'ここに実際のデプロイURL',
  gas:true
};
```

8. `dist/` をゲームのWeb配信先に配置します。ソースの秘密鍵やGoogle認証情報をフロント側へ記載する必要はありません。
9. ニックネーム登録→30秒完走→各期間で順位・得点確認→同じ試合の再送→スマートフォンで接続確認を行います。GASの実行環境・ContentServiceのリダイレクト・CORS・組織ポリシーは実際のデプロイ先で確認が必要です。
10. トリガーで `cleanupHighLow` を1日1回実行するよう設定します。期限切れの試合とレート制限情報のみ削除し、ランキングは削除しません。

## 更新

`dist/engine.js` または `server/ranking-core.js` を変更した場合は `npm run build:gas` で `Code.gs` を再生成してテストします。新しいバージョンを同じHIGH×LOW専用デプロイに反映します。別ゲームの既存デプロイには触れません。

## 本人識別と公平性の制限

GAS版は暗号学的にランダムな識別トークンをブラウザのlocalStorageへ保存し、サーバーはそのSHA-256のみを保存します。これはGoogleアカウント認証ではありません。ストレージ削除・別端末・別ブラウザは別プレイヤーになります。複数名義の作成やトークン窃取を完全には防ぎません。GAS版はHttpOnly Cookieを設定できないため、Node版より識別トークンがJavaScriptへ露出します。

得点・問題ID・回答順序・コンボ・正答率はサーバーで再計算します。経過時間は非負・合計30秒未満と、サーバー発行からの実時間が必要な試合時間に達したことを確認します。しかし、各回答の申告時間が実測どおりであること、自動回答していないこと、背景移行していないことは証明できません。特に平均回答時間を不正に短く申告する余地が残ります。**この制限を承認するか、サーバー主導の問題配信・回答時刻の記録・強いアカウント認証を追加するまで、正式な競技ランキングとしての公開は保留してください。**

GASには実行時間・同時実行数・スプレッドシート操作の割り当てがあります。現在の実装は小規模運用向けです。大量の期間別記録や高負荷ではDBを用いたAPIへ移行することを推奨します。

## このリポジトリでGitHub Pagesを使う場合

専用リポジトリは `https://github.com/asumax1128/highlow` です。GASの実デプロイURLが確定したら、Repository Settings → Secrets and variables → Actions → Variablesに **公開設定値** `HIGHLOW_GAS_URL` を設定します（URL自体は秘密情報ではありません）。Settings → PagesのSourceをGitHub Actionsにして、Actionsから `Publish HIGH LOW test build` を手動実行します。URL未設定の場合は公開処理を失敗させ、未接続のランキングを公開しないようにしています。自動で本番公開するpushトリガーは追加していません。

ワークフローが返した実際の公開URLを使って接続テストしてください。推測のGitHub Pages URLを「公開済み」として案内しません。
