# HIGH×LOW ranking API v1

Node版は同一オリジンの `POST /api/ranking`、GAS版は実際に作成したWebアプリの `/exec` を使います。接続先や認証情報を推測してコードに埋め込んではいけません。

Node版のContent-Typeはapplication/json、GAS版はプリフライトを避けるtext/plainです。いずれも本体はJSON。Node版はCookie、GAS版は本体のtokenで識別します。

```json
{"action":"ranking","data":{"difficulty":"NORMAL","period":"daily"}}
```

| action | data | 主な応答 |
|---|---|---|
| profile | `{}` または `{nickname}` | `player.nickname`, `registered`。GASのみ識別トークンも返す |
| start | `{difficulty}` | `runId`, `seed`, `engineVersion` |
| submit | `{runId,completed:true,answers:[{questionId,choice,elapsed}]}` | サーバー再計算のscore/correct/wrong、期間別updated、periodKeys |
| ranking | `{difficulty,period}` | 上位100行、me、totalPlayers、期間、サーバー時刻 |

- difficultyはEASY/NORMAL/HARD、periodはdaily/weekly/all。
- elapsedはその問題でPLAYINGだった実時間のミリ秒。演出は含めません。
- 得点・正解・コンボなどの申告フィールドは受け付けません。
- 試合はサーバー発行から10分で期限切れ。受付時間は「3秒+30秒+回答数×300ms」から50msを差し引いた時刻以降、60秒の通信・描画猶予内に限定します。各回答時間の真正性は保証しません。
- 記録は初回受付時の日本時間の日付・月曜開始週へ割り当てます。日付をクライアントから指定できません。
- 同一runIdで同じ履歴を再送した場合は同じ記録として処理します。別履歴での再送はDUPLICATEです。
- SQL版はトランザクション、GAS版はスクリプトロックで同時操作を直列化します。GAS版の複数行書き込みはACIDではなく、部分失敗後の再送で3期間のベストを修復します。
- 上位100名の切り口は100レコードです。100位に完全同点が複数いても100名を超えて返しません。順位そのものは全プレイヤーを対象に計算し、本人が100位外でもmeで返します。
- 完全同点の表示順だけは受付時刻、内部プレイヤーIDの順で安定させます。順位を分けるためには使いません。
- ニックネーム未登録の匿名記録は保存しますが表示対象から除きます。後で登録すると同じ匿名IDの記録を表示します。

## エラー

```json
{"error":{"code":"RATE_LIMIT","message":"連続した操作が多すぎます。少し待って再試行してください。"}}
```

Node版は400/401/403/404/409/410/413/415/422/429/500等を返します。GAS ContentService版はHTTPステータスを自由に指定できないため、JSONのerrorも必ず確認します。

クライアントは通信エラーを表示し、試合開始に失敗した場合は記録対象外のローカルプレイを続行します。登録済み試合の送信失敗は、画面上の再送ボタンで再試行できます。通信失敗を登録成功として扱いません。

## 制限

Node版はIP単位でAPI操作120回/分、新規識別情報120件/分。GASはIPを取得しないため識別トークン単位の操作120回/分、トークン未登録の操作と新規識別情報には全体の120回/分上限があります。どちらも1プレイヤーにつき試合開始6回/分、提出12回/分、ニックネーム変更5回/分。固定窓方式のため窓の境界では一時的に上限の約2倍の操作が可能です。

Node版がリバースプロキシの後ろにある場合は、未検証のX-Forwarded-Forを信頼せずソケットのIPを使います。プロキシ全体でIP制限が共有される場合は、その構成に適した信頼済みプロキシ設定やエッジ側のレート制限を追加してください。

匿名IDを大量に取得する不正や自動解答を完全に防ぐものではありません。
